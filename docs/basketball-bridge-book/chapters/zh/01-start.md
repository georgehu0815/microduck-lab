# 两个平衡实验室：本书究竟复现什么

## 一本有边界的实践教材

想象自己站在篮球上：脚移动会改变球的运动，球的运动又会改变脚下的支撑。再想象自己走上由四根绳索悬挂的窄木板：这一步改变了木板的状态，下一步就必须应对新的支撑。这是**相互耦合的平衡问题**，不是把走路动画放到不同背景上。

本书沿着真实 Microduck 仓库，从物理假设、建模、环境、输入输出，走到 PPO 训练、模型导出、评估和七案例 Duck Viewer。读者只需高中代数、函数图像和初步概率知识。公式出现时会解释符号；代码附录提供真实实现，而不是把一个玩具示例冒充完整训练器。

本书采用 **2026 年 9 月 10 日**记录的本地实验作为证据；文档版本为 **1.0，2026 年 9 月 11 日**。版本号表示教材快照，不表示所有技能都已经完成。

| 问题 | 证据支持的回答 |
|---|---|
| 鸭子能在自由篮球上持续保持平衡吗？ | 能。固定指令本地候选策略在六次 60 秒名义条件测试中全部存活。 |
| 能按指令可靠地驱动篮球前进、转向吗？ | 尚未证明；三次前进指令测试均未通过滚动门槛。 |
| 悬挂独木桥是真实工作的物理仿真吗？ | 是：自由木板、四根物理绳索 tendon、起终点平台和可见支架。 |
| 最终独木桥试训成功完成全程了吗？ | 没有。新增 PPO 数据 32,768 步，合格过桥次数为零。 |
| 两个案例都加入 Duck Viewer 了吗？ | 是。七案例等于原有五个加两个，不等于七个技能全部学会。 |
| 已经在实体机器人上验证了吗？ | 没有。本书结果全部来自仿真。 |

成功的篮球行为起点是**用户提供的成熟循环策略**。本地成功环节包括：导入源策略、准确迁移 actor、进一步 PPO 训练、导出一致性验证、持续平衡以及可视化回放。不能据此说随机初始化网络只用 102,400 步就学会篮球平衡。同样，独木桥训练命令成功运行，不代表鸭子成功过桥。

“从无到有”有两层含义。你可以用源代码和必要资产搭出完整的**软件实验**；但不能重建未提供完整记录的上游训练历史，也不能用一句话替代缺失的成熟权重。本书完整提供可复现的本地路线，明确将原策略列为外部前提。`source/` 与 ZIP 是配套代码快照，不包含所有第三方网格、软件依赖和模型权重。

## 学习路线

1. **第一天下午：**阅读假设与建模图，运行环境预检和纯 Python PPO 算术，查看真实连续帧。理解流程不必先训练。
2. **第一次实验：**保留原始资产，建立新的运行目录，执行微型 smoke，逐个检查输出。四步 smoke 只检验管线连通。
3. **测量复现：**执行篮球固定指令微调或独木桥 pilot，导出，关闭辅助后确定性评估，查看完整视频。
4. **研究扩展：**每次只改变一个物理或课程参数，保持评估协议固定，运行多个独立种子，认真记录失败。

调学习率前先读 PPO 章。用曲线判断学习成功前先读验证章。代码附录应与案例章对照阅读，不建议一开始就无背景地看几千行程序。

# 数学和物理：从高中知识出发

## 先理解单位

长度用米，时间用秒，质量用千克，角度用弧度，力用牛顿，力矩用牛顿米。一个没标单位的数字，看起来合理，却可能相差一千倍。

50 Hz 表示每秒向 actor 询问 50 次动作：

$$\Delta t=1/50=0.02\ \mathrm{s}.$$

篮球 60 秒对应 3,000 个控制步；独木桥 20 秒对应 1,000 步。这里是控制步，MuJoCo 内部可能在一次控制期间执行多个更小的物理积分步。环境数增加的是每批数据量，而不是改变一秒有多长。

速度就是位置变化除以时间。0.2 秒前进 0.03 米，平均速度为 0.15 米／秒。加速度是速度变化除以时间。先用有限差分，就能理解仿真任务，不必马上学习微分方程。

力改变动量。一维教学近似为：

$$v_{t+1}=v_t+(F/m)\Delta t,\qquad x_{t+1}=x_t+v_{t+1}\Delta t.$$

这是说明性近似，**不能替代** MuJoCo 的积分、多关节动力学和接触求解。真实仿真还要处理关节、碰撞、摩擦和约束。力矩是使物体转动的作用，等于力乘以垂直力臂。脚的作用力偏离木板中心，即使鸭子仍站直，也可能把木板转动起来。

## 为什么平衡和运动分不开

地面上的支撑脚下方近似不动。在球上，脚施加切向力会使球转动，支撑点随之移动。理想刚性球无滑动滚动时，距离和转角满足：

$$d=r\theta.$$

半径 0.12 米，转过 90 度，即 $\theta=\pi/2$ 弧度，对应 $d\approx0.1885$ 米。以 0.15 米／秒滚动，理想角速度为 $v/r=1.25$ 弧度／秒。这只是尺度检查：滑动、接触形变和转弯都会破坏简单直线公式。

悬挂桥上，重力向下，绳索支撑并约束木板。绳索不是刚性横梁，拉力沿绳方向。代码用 tendon 与限位设置近似所需的绳索行为，具体物理含义由参数决定，不由画面中线条的样子决定。支架可以可见但不参与碰撞。因此视觉图像证明外观，不能完整描述动力学。

“木头”“橡胶”这样的名字不会自动产生正确物理。仿真需要尺寸、质量、惯量、摩擦与接触参数、关节和 tendon 定义。木纹是视觉材质；0.45 千克的木板质量是动力学参数，两者必须分开记录。

## 坐标系：谁的前方？

**世界坐标系**固定在场景中；**机体坐标系**跟着鸭子转动。鸭子转过 90 度，身体前方就不再是世界 x 正方向。如果指令是身体前进，却奖励世界 x 速度，任务就会被错误定义。

平面航向角为 $\psi$ 时，机体速度转换到世界速度：

$$v_x^w=\cos\psi\,v_x^b-\sin\psi\,v_y^b,$$
$$v_y^w=\sin\psi\,v_x^b+\cos\psi\,v_y^b.$$

上标 $w$、$b$ 分别表示 world 与 body，不是乘方。身体速度 $(0.15,0)$、航向 90 度时，世界速度约为 $(0,0.15)$。篮球评估用初始航向作为方向进度参考；独木桥 commander 把导航信息转换成标准机体指令。这都不意味着 actor 直接获得世界坐标。

## 反馈、记忆和部分可观测

**开环脚本**不管发生什么，都重复预定关节目标。**反馈策略**根据当前感知选择下一组目标。如果脚打滑，下一次观测会变化，策略就可能纠正。

机器人拿不到所有仿真状态，只拿到角速度、投影重力、指令、关节信息、上一步动作和保留指令槽。它不能直接读取球心或木板姿态。这叫部分可观测：当前观测相同，过去的运动过程可能不同。篮球 actor 用 LSTM 保存记忆，独木桥使用迁移来的前馈 walking actor。记忆网络不是“透视眼”，只能总结实际进入观测的信息。

训练时随机采样动作，用于探索附近行为；确定性测试时使用导出 actor 的均值。随机策略可能偶尔靠噪声救回一次失衡，而均值策略反而摔倒。因此训练 reward 和导出策略测试是不同实验。

## 算术练习

```python
import math

control_dt = 0.02
radius = 0.12
command_speed = 0.15
steps = round(60 / control_dt)
quarter_turn_distance = radius * math.pi / 2
ideal_angular_speed = command_speed / radius
print(steps, round(quarter_turn_distance, 4), ideal_angular_speed)
assert steps == 3000
assert abs(ideal_angular_speed - 1.25) < 1e-12
```

预期输出：`3000 0.1885 1.25`。这验证的是算术，不是平衡技能。

**练习：**四个环境，每次各采 128 步，得到多少 transition？每个环境经过几秒？累计 32,768 步需要多少批？

**答案：**$4\times128=512$ 步；单环境经过 $128\times0.02=2.56$ 秒；$32768/512=64$ 批。各环境时间相加只是总经验量，不是一次连续 655.36 秒的过桥。

**练习：**为什么高平均 reward 不能证明持续平衡 60 秒？

**答案：**多段表现不错但被摔倒和 reset 分隔的短片段，也可能获得高均值。持续平衡要求不间断的完整回合、首次摔倒判定、合法脚支撑，以及完整时长。
